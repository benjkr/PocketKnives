# Decisions for the whole suite

Check these before changing how the suite is organised; don't reintroduce what was replaced. Each
blade's own decisions are in its `docs/working/decisions.md`.

- **Name and terms**: the suite is PocketKnives, and each tool in it is a *blade* (`blades/<name>`
  in folders, docs and code).
- **The original repos stay as they were**, as a fallback: `quicksnip` (SnipSnap) and
  benjkr/quicktooth. The blades were imported with their full history
  (`git filter-repo --to-subdirectory-filter`), so nothing is lost if they're never touched again.
- **A settings window** that changes the behaviour, looks and settings of each blade, with each
  blade's logo at the top right of its page (the PocketKnives logo on General). On the left, General
  alone, then a "Blades" list: each blade's icon and a box (a switch in Windows 11) for "starts when
  you sign in", so that setting isn't on General. Rejected for that list: General indented with no
  box, General renamed PocketKnives with its own box, the boxes on the right. It has **three looks,
  switched with a setting** (General > Look): **XP**, the raw look (in the user's words: minimal,
  nothing fancy, brutalist, lists on the side, native Windows stuff); **Windows 10**, the same
  native controls with visual styles on; **Windows 11**, the Windows 11 Settings style (glassy,
  modern) in WinUI 3. A Windows 7 look drawn by hand was dropped. The suite icon in the taskbar's
  hidden icons section opens this window. See the [runner spec](../specs/runner.md).
- **One installer for the suite**: `PocketKnives-Setup` (Inno Setup, per user) installs every
  blade into `%LOCALAPPDATA%\Programs\PocketKnives`, each still its own program, with one entry in
  installed apps ([installer](../specs/installer.md)). The blades' separate installs were removed
  from the user's PC.
- **Blade settings come from the blade, with no manifest**: each blade prints its settings (key,
  kind, value, label, choices) and changes them itself
  ([blade settings](../specs/blade-settings.md)), so a setting is defined once, in the blade's
  code. The `blade.json` manifest proposed in the runner design was not built. The settings
  offered are the runner design's list: SnipSnap's three hotkeys and its flash, QuickTooth's
  headset and low-battery level, and since then QuickTooth's tray icon.
- **A choice between looks is picked from pictures** (the `picture` kind): buttons with the
  picture above the label and a frame that slides to the chosen one, chosen by the user from three
  designs and then made smaller. Not chosen: a strip of taskbar with the
  icons at real size, and cards showing both states. A drop-down was the first version. The
  frame is the one thing in the XP and Windows 10 looks that isn't a stock control (four thin
  statics); the pictures come from the blade, drawn at build time, never copied into the repo.
- **Blades and the runner are written in Rust**, `no_std`, each its own small exe on the shared
  `crates/pk` (entry point, heap, arguments, console, registry, single instance, threads); COM and
  WinRT through the `windows` crate. QuickTooth was ported from C# / .NET Native AOT: its exe went from 5.2 MB to about
  0.27 MB with the same behaviour, log lines and pixels, checked against recordings of the C# build.
  SnipSnap was ported from one C file for safety at the same size and speed: 20,480 bytes against
  19,456, the same four system DLLs and 115 imported functions, its per-pixel loops (the dimming,
  the repaint, the clipboard rows) measured no slower than the C on synthetic frames.
  The runner was ported from C# too: `pk.exe` from 1.80 MB to 0.13 MB, and the Windows 11 settings
  app's exe from 4.48 MB to 0.27 MB, with the same Windows App SDK runtime beside it. WinUI 3 runs
  from Rust by subclassing its `Application` through COM aggregation, with bindings generated by
  `windows-bindgen`; the runtime is laid out from pinned NuGet packages, so nothing in the build
  needs .NET. Both match recordings of the C# runner: the same screens pixel for pixel, the same
  files written.
  Rejected: C# Native AOT as the default for blades (a 0.85 MB, 1.2 MB floor per blade), and Rust
  with std (about 100 KB more per exe).
- **Build settings**: smallest code (`opt-level = "z"`), linked by `rust-lld`, which makes the
  same code as MSVC's `link.exe` 512 bytes smaller. Rejected: `opt-level = 3` (QuickTooth's icon
  frame 0.08 ms faster, exes 15–40% bigger) and a newer CPU level (`x86-64-v2`: no faster).
- **Settings reads the blades by asking them**, never from their files: QuickTooth's headsets are
  live, and the runner would need every blade's keys, defaults and checks. The Windows 11 app asks
  once WinUI has launched. Rejected: asking before WinUI loads (the window showed 34 ms sooner,
  its content 13 ms later) or before its control styles load (no measurable change).
- **How blades run together** beyond the runner and settings contract that exist: being decided
  ([runner design](runner-design.md)).
